# Governance

## Authority

Use: latest explicit user requirement; governing repository instructions; approved framework change artifacts; canonical framework/system specifications; approved design/tasks; validated implementation; authoritative external evidence; historical/speculative material. Unresolved material conflicts at the same level block affected work.

## Normative package sources

1. `templates/skills/orchestrator-work-protocol/references/protocol.md`
2. `templates/skills/orchestrator-work-protocol/references/control-packets.md`
3. `templates/skills/orchestrator-work-protocol/references/state.schema.json` when durable state is used
4. integrated framework authority for its own lifecycle and criteria

Adapters and narrative docs point to these sources; they do not fork them. `AGENTS.md` governs contributors to this repository. `templates/project/AGENTS.block.md` is the installed runtime policy. Neither silently substitutes for the other.

## Change policy

Promote no extra stage, stronger model, or CLI support claim without evidence. A stage must cover a distinct risk or demonstrate material benchmark value. Adapter support promotion requires current authoritative sources plus repeatable fresh-process discovery, invocation, generic-worker creation, and fail-closed evidence.

Canonical OpenSpec resources are never package-owned. Package-owned replacements require recoverable backups; unrelated files remain untouched.
