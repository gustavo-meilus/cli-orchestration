# Q: How should cli-orchestration adopt v2 KISS patterns while remaining a portable pure-orchestrator framework?

## Answer

Expanded from both graph vocabularies. Preserve cli-orchestration as a portable pure-orchestrator framework, but adopt lean adaptive routing: direct mode for clear low-risk work; once orchestration is selected, the primary becomes a pure control plane. Default orchestrated topology is implementer plus fresh verifier, with an optional scout for genuine uncertainty and selective high-assurance specialists only when a distinct risk justifies them. Keep one writer, read-heavy parallelism, context-affinity batching, one rework cycle, canonical OpenSpec ownership, thin CLI adapters, tool-aware install/verify, optional resumable state, and evidence-based support promotion. Portability governs role contracts and adapter mappings, not a universal six-stage pipeline.
