# Q: Explain the current cli-orchestration focus and how it should change under the new lean policy

## Answer

Expanded from original query via graph vocab: [project, scope, architecture, framework, independence, orchestration, agent, skills, cli, openspec, process, acceptance]. The current project is a portable pure-orchestrator package built around six fixed logical roles, mandatory independent review, aggregate validation and final audit, optional process/state contracts, and cross-CLI installation. The replacement AGENTS policy conflicts with that thesis: it defaults to direct execution and uses scout only for uncertainty plus implementer and fresh verifier for material changes. Recommendation: pause the 21/39-task change and revise it toward a lean cross-CLI execution policy and distribution toolkit, keeping one writer, fresh verification where material, generic built-in agents, OpenSpec authority, adapters, installer/verifier, and truthful support evidence while demoting six-role workflow, persistent ledger, and exhaustive gates to optional advanced compatibility or removing them.
